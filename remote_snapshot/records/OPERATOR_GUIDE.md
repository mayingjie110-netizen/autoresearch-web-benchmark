- 只从本目录上传规定八个文件；同一 INITIAL_PROMPT.txt 完整粘贴，两边不用提供另一方名称、方案或反馈。

- 不要求回答必须在某个未约定时限内完成；网页等待单独计时。600秒只约束训练进程。

## 每轮：保存、运行、决定、反馈

1. 在远程 records/submissions/ 下手动新建本轮文件夹，例如 A1/。保存完整原始回答 response.txt（不重写），把模型唯一diff代码块内部内容原样另存 model.patch。去除代码围栏是格式提取，不修改补丁内容、缩进、行号或上下文。
2. 正常提交通过统一入口运行（A1示例）：

```bash
bash /data2/home/yingjie/autoresearch/records/run_round.sh A 1 /data2/home/yingjie/autoresearch/records/submissions/A1/model.patch
```

运行前确认GPU0无其他计算进程；有外部干扰先等空闲，不消耗额外模型机会。不要重复启动。脚本不检查补丁的科学合规性，人工必须先做规则检查。

3. 没有可提取补丁，仍计一轮，用同一入口替换第三参数为 --missing；观察到工具使用或明显违规则 --violation，不运行候选。两种情况都保存原回答和证据。

```bash
bash /data2/home/yingjie/autoresearch/records/run_round.sh A 1 --missing
```

4. 阅读真实输出和候选，按已有约束检查有无违规。无观察到违规用 clean，发现违规则 violation。clean 不是后台行为保证。

```bash
bash /data2/home/yingjie/autoresearch/records/finish_round.sh A 1 clean
```

脚本不修复代码。有效且严格更低才提交保留；其他恢复到该轮开始的最佳train.py。原候选、补丁、日志先归档，绝不删除。无效结果记NA，不把0当作崩溃得分。不要手动git reset或修改best记录。

5. 将原回答复制到本轮 records/formal/A/round-1/response.txt。记录介入、偏离、网页等待与人工耗时（未知留空），依照 RESULTS_TEMPLATE.tsv 填表。违规证据及原始截图也存本轮目录。
6. 只向同一产品反馈真实应用输出、退出码、原始run.log附件、review.txt的决定及最佳值；附本轮 next_train.py，并明确它是下一轮唯一权威起点。无运行则明确未运行。补丁解析错误保留 patch_parse.log，应用错误保留 apply_check.log。
7. 可以保留原日志文件并原样粘贴最终汇总作为方便阅读的摘录；不把重写后的文字当作原始日志。不替模型定位错误或给修改建议。它的修复占下一轮。
8. 按A1→B1→A2→B2执行。完成第5轮反馈后，只要求总结，不接收额外实验。下一轮回复可以先保存，但训练严格串行。

## 外因与最后报告

SSH断开、人工放错补丁、存储失败等不是自动的模型失败。保留状态并暂停，两边一致决定如何处理后再继续；不要自行编辑sequence.tsv或重复执行已存在轮次。完整运行之外不增加额外候选测试。
报告每轮分数/失败原因、最佳和最后候选及最终保留分数、补丁率、成功率、可观察遵守率、反馈使用证据、耗时与人工介入。无重复不估计方差，不合成总分。
GPU前后快照不证明运行中没有负载干扰，编译缓存热度和A固定先行也有顺序限制，报告中保留。
