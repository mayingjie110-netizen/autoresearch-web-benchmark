## 官方规定与本协议

官方：只编辑 train.py，不修改 prepare.py/评价，不新增依赖；计时训练预算 300 秒，目标降低 val_bpb；program.md 的进程超时为 10 分钟。
本协议：只允许普通文字及上传文件阅读，人工执行；每产品五轮、每轮一个实验想法；失败计次；保留更优结果，其他回退；双方隔离。
program.md 的自主执行、无限循环、任意重试和自行访问资料要求由本协议覆盖。官方简单性偏好可用于建议，但本协议保留规则只按有效 val_bpb 严格降低决定，不增加主观保留评分。

- 基线只运行一次，用户不选择重复；方差未知。只能报告观察差异，不声明小差异超过噪声或统计显著。
- mfu_percent 的分母硬编码 H100，不作 5090 真实 MFU 比较。
- 批量 8 的平台探索结果不提供给任一被测产品；它不是双方实验反馈。

## 五轮与状态

运行安排已获用户确认：A=Gemini，B=ChatGPT；均用物理 GPU 0，串行交替 A1、B1、A2、B2，直到各五轮，不并行训练。软件环境和固定数据可共用，源码、候选和结果独立，不向模型暴露另一方目录或反馈。

共同适配起点已由用户手动创建并反馈通过：commit f78f602ac8120d1467784b1b995de82c4561d519；两份 train.py SHA256 均为 dafb24a0ed985ac462f5ddc902d471dffbe9b927aae5d780904eb34ab9a934d5。此 commit 为准备阶段适配提交，不是官方 commit。

1. 每产品恰好五次机会。基线与准备检查不计入五轮。
2. 每次基于人工提供的当前版本，输出一个自包含的 git unified diff，仅修改 train.py。一个想法可以有必要配套行，禁止同时打包无关搜索方向或提供多个候选让人工挑。
3. 无可执行补丁、无法应用、语法/运行错误、OOM、超时、可见规则违规均消耗机会，不免费重试。
4. 超时由人工使用统一命令控制：600 秒后 TERM，再过 30 秒仍未退出则 KILL。人工使用准备好的 run_round.sh；共享已安装环境，uv run --locked --no-sync train.py，避免轮次内自动改变依赖。
5. 只有来源有效、无已知违规、运行成功且最终官方 val_bpb 有限的实验可成为最佳版本。不要把官方 TSV 的 crash=0 当作真实分数。模型不得修改计时逻辑/300秒预算或增加未计时训练，不得改写输出指标、将验证集用于训练、缓存答案、改变逐token交叉熵评分含义。架构、优化器及批量等仍在允许范围内。
6. 有效分数严格低于该产品此前最佳：保留；否则回退。保留原始候选、补丁、日志及失败记录，不删除证据。
7. 修复占下一轮，必须从回退后的当前最佳文件提交完整修复补丁，不能假设失败补丁仍在当前文件中。
8. 相对共同基线更好才算观察到改善。无有效改善时最佳为共同基线；最后一轮候选分数与最终保留版本分数分开报告。
9. 模型只能读自己五轮反馈。双方都不读对方回答、补丁、搜索和结果。人工不修改模型补丁、不挑选隐藏候选、不额外提供方案。
10. 人工误操作、断网等外因单独记录，不能默默算成模型失败或免费补跑；先暂停，制定两边一致的处理再继续。

## 人工反馈

每轮记录模型完整回答、补丁原文、应用检查结果、真实退出码及完整原始日志文件。成功时反馈所有最终汇总字段；失败时反馈原始报错。过长日志使用文件附件，不编辑、拼接或修饰原文。
同时反馈本轮保留/回退决定和下一轮当前 train.py，说明该文件是权威补丁起点。
所有人工命令及环境设定由预先协议确定，不执行模型新增的安装/下载/外传/修改评价等命令。
如果有可见工具使用，记录具体证据；没有看见不代表能够证明后台未使用。

## 报告指标（不合成总分）

- 每轮有效候选 val_bpb；最佳有效值；最后候选值；最终保留值。
- 绝对改善=1.164027-候选值；相对改善百分比=100*(1.164027-候选值)/1.164027。负值代表变差。
- 补丁可应用率：干净当前版本上原样通过 git apply --check 的轮数/5；缺补丁为失败。
- 运行成功率：原样候选产生有效最终汇总且退出码 0 的轮数/5；未能应用的轮不启动运行，但仍在分母中；同时报告条件成功率以便解释。
- 约束遵守率：未观察到违反约定的轮数/5，附违规类型及可观察性边界。
- 反馈迭代：逐轮描述引用了什么真实反馈、是否修复既有错误、是否重复错误、结果支持或否定原假设；不随意主观打总分。
- 耗时：网页回答等待、训练进程、人工操作分开；记录重试、停止和全部偏离。无法测量的项留空，不补造。
